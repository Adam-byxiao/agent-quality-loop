# 安全：凭据、出站与公开投影

平台同时持有三类敏感物：上游凭据、真实业务对话、可对外分享的轨迹。三者需要三种不同的保护，不能混在一起。

## 1. 凭据：加密 + 绑定 + 成对备份

- 凭据用对称加密存储，主密钥放在**数据库之外**的独立文件或环境变量；
- 密文绑定三元组：`projectId + baseUrl + externalProjectId`；
- 任何一项变化，旧凭据立即失效，必须重新录入；
- API 层没有"取明文"的端点，只能在服务端解密后直接用于出站请求；
- **主密钥与数据库必须成对备份**：密钥丢失后库里的凭据全部不可恢复，且不能"重新生成"了事。

绑定三元组不是洁癖：如果只按项目 ID 绑定，把连接地址改成攻击者服务器后，平台会把旧凭据发过去。绑定地址与外部项目 ID 之后，改地址等于主动作废凭据。

## 2. 出站：一个策略入口，三条硬规则

所有平台发起的外部请求都经过同一套出站策略：

```text
url → 解析主机 → 与允许列表比对 origin → 解析并固定一个 IP
    → 非全局单播？检查显式 CIDR 例外
    → 不跟随重定向、不使用环境代理
```

三条硬规则：

1. **origin 白名单**：协议 + 主机 + 端口精确匹配，不允许"同域即可"；
2. **解析后固定 IP**：防止 DNS 重绑定——校验时解析一次，连接时用同一个 IP；
3. **私网地址默认拒绝**：回环、链路本地、内网段都需要运维显式登记 CIDR，不能靠"看起来是内网"自动放行。

另外：只读客户端不走通用 HTTP 封装，固定路由、固定方法，避免"传个 URL 就发请求"的 SSRF 面。

## 3. 浏览器侧：Cookie 与 CSRF

- 会话令牌只存哈希；Cookie 使用 `HttpOnly`、`SameSite=Strict`、限定 `Path=/api`；
- 所有写操作同时校验 `Origin` 命中允许列表 **和** 自定义请求头（如 `X-Requested-With`）；
- 反向代理后必须显式信任代理，否则登录限流会把全站算成一个来源；
- HTTPS 才允许开启 secure cookie；内网 HTTP 部署是已知限制，见 [边界](07-limits.md)。

## 4. 公开分享：冻结的脱敏投影

轨迹分享不是"给个链接看原数据"，而是：

1. 创建分享时，把当下的数据**投影**成一份脱敏快照；
2. 移除 `userId`、`sessionId` 等可关联字段；
3. 数据库只存令牌的哈希，明文只在创建时显示一次；
4. 链接有有效期，可随时撤销；
5. 分享页不连上游——上游之后变化或被清理都不影响已冻结的内容。

"冻结"是安全属性也是可用性属性：它保证分享的内容不会在你不知情时被上游改写。

## 5. 诊断日志

- JSON Lines、按大小轮转；
- 记录请求结果、错误码、上游调用阶段、请求编号；
- **不记录**凭据、请求体、业务标识；
- 对外报错使用稳定错误码，500 才带请求编号与异常类型，堆栈只在服务端日志里。

## 6. demo 的取舍

demo 没有实现登录、凭据加密与分享（没有这些东西需要保护），但保留了：

- 外部调用全部集中在一个传输层，接口可替换；
- 报告里明确写出"未实现"的部分。

安全设计的展示价值不在"代码里有个加密函数"，而在**每条规则的失效模式**：

| 规则 | 不做会怎样 |
| --- | --- |
| 凭据绑定地址 | 改连接地址即可把旧凭据发往任意主机 |
| 固定解析 IP | DNS 重绑定绕过白名单 |
| 非全局地址显式放行 | 内网元数据服务被当作普通上游 |
| 写操作双重校验 | 跨站请求伪造 |
| 分享冻结投影 | 上游数据变化或泄露用户标识 |
| 日志脱敏 | 凭据与业务内容落盘 |
