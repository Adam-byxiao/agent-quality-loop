# ADR-0002：指纹决定身份，ID 不是身份

## 背景

失败轮次会被报告、批次、闭环、外部引用同时指向。重复导入同一段会话时，如何判定"这是同一条失败"？

## 备选

1. 用数据库自增 ID 作为身份，重复导入时按外部 ID 查重；
2. 用会话 ID + 轮次序号查重；
3. 用内容指纹查重，指纹写进唯一索引。

## 决定

选 3：

```text
fingerprint = sha256(session_id \x1f turn_index \x1f score_name \x1f 用户输入)
```

- 同一版本内唯一；
- 自动导入**只填空列**，绝不覆盖已有 ID；
- 回放主键升级走显式接口，不由后台悄悄替换。

## 代价

- 用户输入变化会生成新记录，而不是更新原记录；
- 指纹字段参与了业务语义，改算法需要迁移；
- 同一内容来自不同来源（评测运行 vs 会话导入）默认算两条，除非显式关联。

## 为什么

身份一旦可变，所有引用都会漂移：昨天指向失败轮次 A 的批次，今天可能指向内容已经变化的 A。指纹把"同一条失败"钉在内容上，代价是宁多不少——旧证据不应被新内容改写。

## 证据

demo 的重复导入返回 `0 new`，失败轮次集合不变；`replay_key` 只作为可回放性标识，不参与指纹。
