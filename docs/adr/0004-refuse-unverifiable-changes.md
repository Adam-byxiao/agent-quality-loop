# ADR-0004：拒绝无法验证的改动

## 背景

优化器可以返回四类改动：主提示词、技能正文、工具描述、参数描述。回放服务只支持**替换主提示词**，历史、工具定义、技能正文都保持原样。

如果平台接受一份包含工具描述改动的候选，回放验证的仍然只是旧工具定义。

## 备选

1. 接受整份候选，只验证主提示词，其余字段"先存着"；
2. 只取主提示词部分，其余字段丢弃，记录"部分验证"；
3. 整份拒收，直到上游支持完整候选注入。

## 决定

选 3：

- 候选字段白名单只有 `main_template`；
- 出现 `skill_template` / `tool_description` / `parameter_description` 任一个 → 整份拒收；
- 拒收发生在回放**之前**，不消耗验证成本；
- 拒收原因写进错误历史，下一次提案可以看到。

## 代价

- 优化器的能力被浪费，收敛变慢；
- 有些缺陷本来就需要改工具描述才能修，只能停在 `stalled`；
- 需要和上游对齐"什么时候支持完整注入"，这是一个外部依赖。

## 为什么

"部分验证"是最危险的中间态：报告上写着"已验证"，实际上验证的不是提交的那份改动。一旦这种记录进入流程，后续所有结论都不可信。

**宁可少修，不造假通过。**

## 证据

demo 第 1 次提案包含 `tool_description`：事件显示"候选包含回放无法注入的字段，整份拒收"，回放调用次数为 **0**，条目 `attempts` 前进到 2，下一次提案携带这条错误历史。
