# ADR-0007：冻结结果，重扫不碰上游

## 背景

一次评测的真实轮次有副作用，且上游数据会被清理或变化。事后重看报告时，应该重新读取上游吗？

## 备选

1. 每次查看都实时读取上游；
2. 缓存但要过期，过期后重读；
3. 结果写入时冻结成 JSON，重扫只读这份 JSON。

## 决定

选 3：

- 评测运行写入时保存逐用例、逐轮的完整结果；
- "重扫"只重放这份 JSON，不访问上游；
- 失败轮次的回放主键、历史、起始资产同样冻结进批次；
- 分享页使用冻结的脱敏投影，不连上游。

## 代价

- 存储增长；
- 上游修复数据后，平台看不到（需要新建一次运行）；
- 冻结内容与上游不一致时，以平台冻结的为准，需要向使用方解释。

## 为什么

- 报告必须可复现：同一个批次，今天看和下周看结论一致；
- 上游没有"历史时点"查询，重读得到的是现在，不是当时；
- 真实轮次不可重跑，丢掉证据就只能重新付费产生副作用。

判断标准：**如果重新获取一次可能得到不同答案，就必须冻结。**

## 证据

demo 的导入把会话与评分固化在本地 SQLite；修复使用的 `replay_key` 与历史来自这份固化数据，批次执行期间不再访问观测平台。
