# ADR-0005：uncertain 不是通过

## 背景

评分来自外部系统，可能有多行、冲突、非 0/1 的值，或者根本还没写回来。平台如何聚合？

## 备选

1. 多数票；
2. 取平均，低于阈值算失败；
3. 一致才判定，否则 `uncertain`；
4. 优先信任最后一次评分。

## 决定

选 3，并分两种情况：

- **同一观测的多行**＝同一判断重复执行：全部一致才判定，冲突记 `uncertain`；
- **不同观测的多行**＝一轮里的多个评分主体：逐个判定，**任一失败即该轮失败**；
- 非 0/1 的值不映射，记 `uncertain`；
- `uncertain` 不计入通过率，也不触发修复。

## 代价

- 更多轮次无法自动处理，需要人工看；
- 报告里"未判定"数量可能很大，看起来不好看；
- 需要向使用方解释"为什么不能给一个数"。

## 为什么

- 多数票会掩盖判断不稳定；
- 平均是平台发明的判定，没有任何一方做过这个判断；
- 把 `uncertain` 当通过，等于用"不知道"换取好看的通过率。

## 证据

demo 的评分聚合实现与文档一致；报告里没有"部分通过"这种状态。内部版的同口径测试覆盖了 0/1 冲突、跨观测任一失败、0.5 值三种场景。
