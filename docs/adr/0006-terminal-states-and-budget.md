# ADR-0006：终态与预算，只有 converged 算通过

## 背景

一个批次可能因为多种原因结束：全部修好、明确失败、预算用完、人工停止、技术异常。用什么词描述结束？

## 备选

1. 布尔值 `success: true/false`；
2. `success` + `error`；
3. 五个明确的终态 + 每条的尝试预算。

## 决定

选 3：

| 终态 | 含义 |
| --- | --- |
| `converged` | 所有可回放条目通过，回归全过 |
| `failed` | 回归存在明确失败 |
| `stalled` | 预算耗尽，仍有条目未通过 |
| `stopped` | 人工停止 |
| `error` | 技术异常，无结论 |

**只有 `converged` 算通过。** 每个条目有 `max_attempts`；耗尽记 `budget_exhausted`，不是"失败"（失败是明确的否定，预算是没有结论）。

## 代价

- 下游需要区分五个值，不能只判断 true/false；
- 报告更长；
- 需要产品与使用方接受"不是所有批次都有结论"。

## 为什么

- `stalled` 与 `failed` 的后续动作完全不同：前者加预算或改上游，后者查候选方向；
- `stopped` 是人的决定，不能混进质量结论；
- `error` 是系统问题，重试可能就好，不能算业务失败；
- 布尔值会逼着实现者把"不知道"归到某一侧。

## 证据

demo 的报告顶部永远显示终态与停止原因；停止按钮产生 `stopped`，不会显示为 `converged`。
