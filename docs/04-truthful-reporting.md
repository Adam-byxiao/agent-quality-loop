# 诚实口径：不确定不是通过

这一页是整套设计里最值钱的部分。功能可以少，口径不能错。

## 四条规则

### 1. `uncertain` 是一等公民

`uncertain` 表示**没有判定**：

- 不是通过；
- 不是失败；
- 不能计入通过率的分母或分子；
- 不能用来触发修复（修复需要明确的失败证据）。

界面上它与 pass / fail 并列显示，报告里单列数量。任何"把 uncertain 算成 pass"的聚合都是口径错误。

### 2. 冲突评分不取平均

同一个评分名可能对应多行：

| 情况 | 判定 |
| --- | --- |
| 同一观测上的多行（同一判断重复执行） | **全部一致**才算判定；不一致 → `uncertain` |
| 不同观测上的多行（一轮里的多个评分主体，如多次工具调用） | 逐个判定；**任一失败即该轮失败** |
| 值不是 0/1（0.5、标签、空） | 不猜，`uncertain` |

为什么同一观测要"全体一致"：重复执行是同一个判断的重试，出现分歧说明这个判断本身不稳定。取多数票会掩盖不稳定。

为什么不同观测要"任一失败"：一个轮次调了三个工具，两个成功一个失败，整体就是失败。取平均会让一次坏调用藏在两次好调用后面。

### 3. 对齐不猜相似度

比较两条轨迹时，步骤按显式身份对齐：

```text
(类型, 名称, 步骤类型, 工具名, 同名出现序号)
```

- 改名 → 左侧移除 + 右侧新增，**不做相似度猜测**；
- 插入一个不同名的步骤，不影响后续配对；
- 只比较步骤摘要，明确声明不含完整载荷。

"看起来像同一步"是模型的判断，不是事实。比较报告不应该发明事实。

### 4. 每一层都写覆盖范围

| 层 | 事实 | 界面/报告必须写 |
| --- | --- | --- |
| 列表扫描 | 读了 N 条观测，可能被截断 | "本次覆盖 N 条，未读到末尾" |
| 深采样 | 只读了最近 M 条载荷 | "覆盖 M 条 / 共 N 条候选" |
| 分位统计 | 被截断时低估 | "有 K 条轨迹受影响" |
| 回归 | 部分轮次不可回放 | "8 通过，1 排除（无回放主键）" |
| 候选 | 只验证了主提示词 | "技能/工具改动未验证，平台拒收" |

**不把样本当总体**不是一句免责声明，是 UI 的硬约束：没有覆盖范围数字的图表不许上线。

## 反例清单

以下都是真实项目里出现过、值得警惕的写法：

| 写法 | 问题 |
| --- | --- |
| "平均耗时 15.8 秒" | 混合了 Agent 与评分器两个分布，既不描述前者也不描述后者 |
| "通过率 80%"（含 uncertain） | uncertain 被当成通过或失败，两种都错 |
| "已验证 4 类改动" | 回放只注入了主提示词，其余三类根本没验证 |
| "共 37 条轨迹" | 上游不给总数，37 是本次扫描窗口 |
| "分位 P90 = 12s"（截断样本） | 真实 P90 更高，报告没标低估 |
| 报告只写"完成" | 没写终态是 converged 还是 stalled |

## 报告的最小结构

一份可接受的报告至少包含：

1. **终态与停止原因**：`converged` / `stalled` / `failed` / `stopped` / `error`；
2. **起点与终点**：起始资产哈希、最终资产哈希、资产序号变化；
3. **逐条证据**：每个失败轮次的尝试次数、每次回放的逐次结果、拒收原因、接受依据；
4. **回归结果**：逐条通过/失败，以及排除项与原因；
5. **局限声明**：这次没有验证什么（技能/工具改动、不可回放轮次、单次回归）；
6. **覆盖范围**：所有统计口径的边界。

demo 的报告页就是按这六项渲染的。

## 一条自检问题

设计任何指标时问一句：

> 如果这个数字是错的，用户能从界面上看出来吗？

如果答案是"不能"，就必须补上覆盖范围、样本量或不确定性说明。
